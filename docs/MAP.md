# 乡贤分布地图

本项目的核心页面:`src/pages/map/index.vue`。

---

## 一、技术方案与成本

| 能力                  | 怎么实现                                           | 要不要 key / 花不花钱        |
| --------------------- | -------------------------------------------------- | ---------------------------- |
| 底图                  | uni-app `<map>` 透传微信原生地图(底图就是腾讯地图) | ❌ 免费无 key                |
| 打点、气泡、点聚合    | `markers` + `joinCluster`                          | ❌ 免费无 key                |
| 逆地理编码(坐标→地址) | 腾讯位置服务 WebService API                        | ✅ 需 key,**且必须后端代理** |
| 地点搜索、路线规划    | 同上                                               | ✅ 需 key                    |

`<https://lbs.qq.com/>` 个人开发者免费配额对本项目量级绰绰有余。
**key 绝不能出现在小程序端** —— 小程序包是可解包的,key 漏出去会被人盗刷配额。
所以这类调用一律由 `tsa-api` 转发。

### 为什么不用高德

微信 `map` 底图是腾讯的 **GCJ-02**。混用高德的 key/SDK 会引入另一套坐标偏移,
表现为整体偏移几百米。这是新手最常踩的坑:**统一用腾讯系**。

## 二、数据分布是这张页面的设计核心

mock 数据(`scripts/gen-mock.mjs`)按**潮汕乡会的真实人口结构**加权,
300 条**刻意不均匀**:

| 区域                                  | 条数 | 占比 | 作用                             |
| ------------------------------------- | ---- | ---- | -------------------------------- |
| 潮汕本地(汕头 92 + 潮州 14 + 揭阳 14) | 120  | 40%  | 演示 `join-cluster` 聚合的主战场 |
| 珠三角(广深莞佛珠中惠)                | 99   | 33%  | 潮商在外最密集区,第二密集层      |
| 长三角(沪杭甬温苏宁)                  | 36   | 12%  |                                  |
| 京津冀(北京、天津)                    | 24   | 8%   |                                  |
| 其他省会(蓉汉长厦闽昆陕)              | 21   | 7%   | 稀疏点,演示缩放层次              |

坐标 = 真实城市经纬度 + `±0.15°`(外地)/ `±0.05°`(区县内)随机扰动,
避免几百个点完全叠在同一像素上。扰动用**固定种子**,保证每次生成一致。

**均匀撒满全国是最糟的做法**:地图上看不出任何信息,聚合也演示不出来,
等于把最亮的功能做废。改分布请同步改这份表格。

## 三、必须知道的实现约束

### 1. `<map>` 是原生组件,层级最高

普通 `view` 浮不到它上面,`z-index` 无效。覆盖 UI 必须用 `cover-view` / `cover-image`。

本项目的分工:

- **成员卡片**用 `cover-view` —— 它必须浮在地图上;
- **筛选面板**用 `t-popup` —— 它打开时本来就该盖住地图。

`cover-view` 的两条限制:

- **不能嵌套 TDesign 组件**(只支持基础标签);
- 支持的 CSS 是子集,flex 的 `gap` 等属性不生效,要逐个写 `margin`/`padding`。

> 另:本页 `cover-view` 的样式里颜色是**硬编码**的 `#0052d9` 而不是
> `var(--td-brand-color)`。原因是 cover-view 由原生层渲染,
> CSS 自定义属性是否透传**取决于微信基础库版本,本项目未在真机上验证**。
> 换主题色时请一并手改这几处(见 [TASKS.md](TASKS.md) 的 L1-1),
> 或在你的基础库版本上实测确认可用后再改回变量。

### 2. `marker.id` 必须是 number

成员 id 是字符串(`m0001`),不能直接当 `markerId`。做法:用数组下标当 id,
另存一张 `Map<number, MemberMapPoint>` 反查。见 `byIndex` computed。

### 3. 聚合点点击的区分

点聚合气泡时,微信自动展开该聚合点,此时回传的 `markerId` **不在反查表里**。
所以 `onMarkerTap` 里 `byIndex.get(id)` 返回 `undefined` 时**不弹卡片**。
不加这个判断,会出现"点聚合气泡弹出一个不相干的成员卡"的诡异 bug。

### 4. 不要开 `show-location`

第一阶段渲染的是**成员的坐标**,不是**用户的位置**。所以完全不需要定位。

一旦打开就会触发 `scope.userLocation` 授权,连带需要:AppID 隐私协议配置 +
`manifest.json` 声明 `requiredPrivateInfos: ["getLocation"]`。
**避开它,第一阶段才能不依赖任何外部审批就跑起来。**

### 5. 不要用 `regionchange` 回写 center

```js
// ✗ 看着合理,实际会抖
@regionchange="e => center = e.detail.centerLocation"
```

`:latitude` 是双向绑定的受控属性,拖动结束后回写会让地图"弹回"或持续抖动。
本项目**只在点「家乡/全国」按钮时主动改 center**,用户自由拖动不回写。

若将来要做「当前视野内成员数」,应该监听 `regionchange` 读 `e.detail`
但**不回写** center。

### 6. `iconPath` 规则

要换自有图标时:必须 **PNG**(不支持 SVG),放 `/static/` 下用本地路径,
建议 28×28 起。外链图片还要配域名白名单,没必要。
当前刻意**不传 iconPath**,用微信默认红色图钉 —— 少一个需要素材的环节。

### 7. 沉浸式页面要自己让开状态栏

地图页 `navigationStyle: "custom"`,没有原生导航栏占位,
所以按钮要用 `uni.getSystemInfoSync().statusBarHeight` 加安全间距往下推,
否则压在信号栏上。

### 8. H5 端表现不同

编译到 H5 时 uni-app 用的是另一套地图实现,`cover-view` 行为有差异。
第一阶段只验证微信小程序;将来出 H5 时**地图页需要单独回归测试**。

---

## 四、要"自动框住所有点"用 includePoints

手动设 center + scale 很容易漏点。正确做法:

```js
uni.createMapContext('memberMap').includePoints({
  points: [{ latitude, longitude }, ...],
  padding: [60, 40, 60, 40],
})
```
